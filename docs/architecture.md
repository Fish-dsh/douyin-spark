# 工作原理

一个夜晚的完整链路如下。想改逻辑，先读完这张图和后面的"为什么"。

```
cron 00:00 ──► run_cron.sh ──► spark.py ──► src/scheduler.run()
                 │                │
                 │                ├─ 1. 窗口校验：send_window 只约束「开始时刻」，跑进凌晨不算违规
                 │                ├─ 2. 登录态：恢复 runtime/storage.json → 失效则 auto_login 重登
                 │                ├─ 3. PID 锁：拿不到锁就退 4（绝不当成功）
                 │                ├─ 4. 发现：扫描聊天列表 → need(火花需续) / active(已续,跳过) / 置顶(强制)
                 │                ├─ 5. 逐个发送：打开会话 → 点"续火花"表情 → 列表出现新气泡＝发送成功
                 │                │      失败降级：文字「续火花」；再失败 → 自愈分类 → 重试/重开
                 │                ├─ 6. 幂等落盘：runtime/state.json 记下今天已发的人
                 │                └─ 7. 退出码：0 完成 / 1 异常 / 2 未登录 / 3 需冷启动重跑 / 4 撞锁
                 └─ 硬截止 01:35：距截止不足 20 分钟不再起新一轮，timeout 按剩余时间收窄
cron 01:45 ──► src/health_check.py：state 日期是不是今天 + 日志里当晚有没有「收尾」
```

## 为什么是这么设计的

- **必须"有头"浏览器**：`headless` 一旦为真，抖音会拦；弱机上无头渲染还容易挂死。所以统一跑在 Xvfb 虚拟显示（`:99`）上，`health_check` 里有一条断言专门守着这个配置。
- **发送成功的第一判据是"聊天列表里真的多了一个气泡"**，不是"点了按钮"（后者在风控态下会静默无效），也不是"面板关闭"（面板关了但零新增时，恰恰说明点了个空）。面板关闭只在"证据读不到"时作为降级判据，日志会标「降级」。
- **自愈不再让 AI 改源码**：早期版本用 LLM 在运行时修 bug，实盘一次没修成，还把发送窗口烧穿。现在是「错误分类 → 本地策略表 → 告警」，零 API、毫秒级、可预测（见 [self-heal.md](self-heal.md)）。**注意**：项目里另有一条独立的模型调用链 `src/vision.py`（视觉兜底），默认开、只在选择器全失效时触发，与自愈无关，别混为一谈。
- **窗口外补跑不受限**：`send_window` 只约束自动开始时刻，`--force` 手动补跑随时可以，但仍受 01:35 硬截止保护。
- **时间预算要一次钉死**：`timeout 90m`（两账号串行实测约 60 分钟）+ 硬截止 01:35（保证 01:45 的巡检一定跑在任务结束之后），两者必须同时存在，改一个就要回头看另一个。

## 模块职责

| 文件 | 职责 |
| ---- | ---- |
| `spark.py` | 入口：`python spark.py [--force|--dry-run]` |
| `login.py` | 入口：`python login.py [--password|--manual]`（薄壳，实现在 `src/login.py`） |
| `run_cron.sh` | 定时入口：cron 调它，重试 / 超时 / 硬截止都在这里 |
| `run_dev.sh` | 开发入口：`config.dev.json` + `runtime-dev/`，不碰正式账本 |
| `logutil.py` | 日志：控制台 + 持久文件句柄（轮转安全） |
| `src/scheduler.py` | 主流程编排：窗口、逐账号、补扫、退出码 |
| `src/session.py` | 浏览器生命周期、登录保障、内存回收、资源拦截 |
| `src/login.py` | 登录态存取 / 密码重登 / 退避 |
| `src/discovery.py` | 好友发现编排（置顶强制、active 跳过、need 待发） |
| `src/spark_status.py` | 火花状态识别：4 条策略（CSS 类名 → 文本特征 → 火焰图标 → 结构兜底） |
| `src/sender.py` | 打开会话 / 发表情 / 发送确认 / 文字兜底 / 重试 |
| `src/finder.py` | 选择器与渲染等待工具 |
| `src/self_heal.py` | 自愈门面：错误分类 → 本地恢复策略 → 告警（零 API） |
| `src/recovery.py` | 纯函数决策表（无依赖，便于单测） |
| `src/health_check.py` | 每日巡检：state 日期 + 日志收尾 + 有头配置断言 |
| `src/streak_history.py` | 火花历史覆盖门禁（近 3 天该出现的人今天是否还出现） |
| `src/perf.py` | 三档性能参数表（浏览器参数 + 等待/超时项，可按机器强弱选） |
| `src/events.py` | 结构化事件流（`runtime/events.jsonl`，与日志解耦） |
| `src/weekly_report.py` | 周报：只读日志，回看 7 个已结束的夜晚 |
| `src/stealth.py` | 浏览器特征伪装（只伪造自动化标记，不碰滑块/验证码） |
| `src/vision.py` | 视觉兜底：多模态粗定位 + DOM 现场取证（左栏先打码） |
| `src/vision_cv.py` | 纯 OpenCV 找红色发送按钮（无网络、无模型，毫秒级） |
| `src/net_sniff.py` | 被动旁路嗅探，仅作"接口改版"的诊断金丝雀 |
| `src/debug.py` | 调试截图与页面 dump |
| `src/config.py` | 配置 / 状态 / 窗口判定 / 环境变量 |
| `tools/` | 运维脚本（不参与发送主链路）：心跳看门狗、策略统计、网络观测 |
| `tests/` | unittest 全量测试 |
| `docs/` | 本目录：架构、配置、部署、运维、自愈、开发 |

## 一次发送到底做了什么

1. `discovery` 拿到聊天列表快照，按火花状态贴标签：`need`（有火花、今天没互动）、`active`（今天已经互动过）、`pinned`（置顶）。
2. `sender` 打开会话 → 点"续火花"表情入口 → 在表情面板里点那个内置表情。
3. 判定（`src/sender.py` 的 `_evidence`）：① 列表出现新气泡/尾部窗口移动 = 硬证据，成功；② 证据读不到但面板关了 = 降级判成功（日志标「降级」，供统计失证比例）；③ 证据可读且零新增 = **判未发送**，降级发文字"续火花"；④ 面板没关且窗口用尽 = 记 unknown，不猜。
4. 成功就把这个好友记进 `runtime/state.json` 的今天记录；失败则交给 `self_heal` 分类，决定重试 / 重开会话 / 放弃告警。
5. 一轮扫完再看队列里还有没有 `need`，有就补扫（受硬截止约束）。
