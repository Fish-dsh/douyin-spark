# 为什么这个项目必须"有头"跑

这份文档是 **headless 不可行**的第一手实测记录。

项目里有一条硬约束写得到处都是：`headless` 必须是 `false`，必须跑在 Xvfb 虚拟显示上。很多人第一次看到会想"不就是一个开关吗，无头不是更省内存？"

这台 ARM 小板上实测过，答案是：**不行**。

## 实测结论

| 组 | 做法 | 结果 |
|---|---|---|
| A | `--dump-dom` + `--virtual-time-budget=12000` 一次性渲染 | DOM 完整（1.2MB）、截图正常 —— **看起来能用** |
| B | CDP 真实交互会话，试了 6 组参数（等 11/26/30/75 秒、禁后台节流、强制出帧、bringToFront、显式 SwiftShader、虚拟时间策略） | **全部停在骨架屏**，正文长度只有 3～19 字符，登录框从未出现 |
| C | GPU 观察 | 全程 SwiftShader 软件渲染，Mali-G31 / Panfrost **完全没参与** |

A 组的完整 DOM 不代表能用 —— 它只证明"页面代码能跑完"，不证明"画面能渲染出来"。判据以 B 组为准。
